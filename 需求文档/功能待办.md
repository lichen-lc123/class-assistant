## TODO-001：个人改期后的作业匹配

### 复现条件与现象

1. 同一学期有两张课程名称、老师相同，但全部上课日期或起止时刻不同的课程卡片，各有独立关联的作业。
2. 用户从模板选入其中一张卡片，再通过“调整个人安排”把全部日期和起止时刻改成另一张卡片的安排。
3. 原课程引用仍然保留，符合“原课程关联”的作业继续显示；修改后的课程身份又与另一张卡片一致，符合“课程名称、老师、全部日期及起止时间”的作业也会显示。
4. 当前这两种匹配使用“或”合并，因此该特定条件下，课程详情可能同时出现两班作业。不是任意改一个日期就会发生。

涉及代码：[作业匹配](../server/homework.mjs)、[课程身份计算](../server/course-identity.mjs)、[个人安排保存](../server/timetable.mjs)。

### 待确定与处理方向

- 明确原课程引用与个人时间身份的匹配优先级，不把不同教学班的作业无条件合并。
- 个人改期后是否改变作业归属，应明确业务规则后实现，不能凭改期默认为已选入另一张课程卡片。
- 工程管理导论暂不新增秋冬班字段、不拆分校历、不修改现有课程日期或管理员维护内容。
- 其他课程已约定的“同名同老师共享作业”规则需要保留，不能为修复此问题全部取消。

### 验收要求

- [ ] 同名同老师、不同日期或时段的导论作业，按确认后的规则准确展示，不因两条匹配规则取并集而混入另一班。
- [ ] 仅修改教室、仅修改某次时间、全部改成另一张卡片的安排，分别验证。
- [ ] 主动移除原课并添加正确卡片后，显示正确课程对应的作业。
- [ ] 我的作业、课程详情、工作台及手机端结果一致；个人作业、完成状态、计划完成时间及附件不丢失。

## TODO-002：移除课程后被模板更新补回

### 复现条件与现象

1. 用户先导入模板，随后主动移除其中一门课程，再从“课程卡片组合”加入正确课程。
2. 当下旧课已移除，新课及其作业正确显示，模板中的其他课程保留。
3. 管理员以后更新模板版本，即使只修改模板名称，成员同步仍会按模板完整成员补齐课程。
4. 由于没有保留用户主动排除此课程的记录，被移除的旧课会重新出现在个人课表中。

涉及代码：[模板成员同步及个人课程移除](../server/timetable.mjs)。

### 处理方向

- 记录用户主动移除模板课程的意图，后续模板同步尊重该排除。
- 区分主动移除、普通版本落后补同步及用户主动重新选入，不能用“停止全部同步”规避问题。
- 兼容多个模板、直接添加的课程卡片及现有个人安排；数据结构变更如有需要，单独设计兼容方案。

### 验收要求

- [x] 移除旧课并添加正确卡片后，模板改名、修改课程、增删成员均不会把主动排除的旧课补回。
- [x] 模板中的其余订阅课程继续正常更新，新添加的正确课程保留。
- [x] 用户主动重新添加已移除课程时行为明确，并继续检查时间冲突。
- [x] 多模板引用与直接卡片来源分别验证，避免误删其他来源课程。
- [x] 电脑和手机一致；保留服务器账号、原课程、作业、附件及个人状态，不用本地数据库覆盖。
