## 服务器上的文件和服务

| 内容 | 位置或名称 |
| --- | --- |
| 当前运行版本 | `/opt/homework/current`，指向对应发布目录 |
| 发布目录 | `/opt/homework/releases/<发布提交号>` |
| 正式数据库 | `/var/lib/homework/homework.sqlite` |
| 备份 | `/var/lib/homework/backups/` |
| 环境配置 | `/etc/homework/homework.env` |
| 网站后端 | `homework.service`，以 homework 专用用户运行 |
| HTTPS 网关 | `homework-web.service`，以 homework-web 用户运行 |
| 自动备份任务 | `homework-backup.timer`，北京时间每天 03:15 后五分钟内运行 |
| Node | `/opt/class-assistant-runtime/node-v24.22.2-linux-x64/bin/node` |

网站、HTTPS 网关和备份任务均已设置开机启用。SQLite 是后端使用的内置数据库，不需要额外启动数据库进程；重启服务会继续读取同一个数据库文件。数据库、备份与凭据不进入 Git 或网站静态目录。

本次服务器没有已运行的 Nginx，使用单文件 Caddy 2.11.8 提供 HTTPS 和证书自动续期。网关只将网站请求转给本机 127.0.0.1:3001；该后端端口没有直接对外监听。Let’s Encrypt 已签发 IP 地址证书，使用 shortlived 配置，由网关自动续期。访问者无需安装自签名根证书。

配置参考：[Caddy TLS](https://caddyserver.com/docs/caddyfile/directives/tls)、[Let’s Encrypt IP 证书说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)。

## 经常更新时怎样做

1. 在电脑上修改源码，完成测试和前端构建。
2. 将源码提交到 main；在 deploy 分支合并源码并保存新构建的 dist，记录发布提交号。只拉取 main 不会获得已构建的前端。
3. 将发布程序包传到服务器的新发布目录，核对压缩包摘要；程序包不包含数据库或环境文件。
4. 在新目录使用 `scripts/check-release.mjs` 验证，它使用独立内存数据库。新版本有数据库升级时，先在正式库的备份副本上核对兼容性。
5. 更新前停止网站写入并生成一致性备份；把 current 切换到新目录，重启 homework.service，等待本机首页返回 200，再检查公网 HTTPS 和实际业务。版本切换会有短暂重启。
6. 新版本失败时，停止写入，按兼容性判断回退程序还是同时恢复更新前备份。不要在网站运行、仍有人写入时直接覆盖数据库。

首次部署的数据迁移只执行一次。日后更新不得重新复制电脑里的旧数据库，否则可能覆盖同学在线新增的数据。

目前没有启用“推送代码即自动覆盖生产”。可以继续让助手执行发布与核对；若要无人值守发布，后续再单独配置权限、检查及失败回退。

## 常用维护命令

在服务器中查看运行及备份计划：

```bash
systemctl status homework.service homework-web.service --no-pager
systemctl list-timers homework-backup.timer --no-pager
```

额外做一次备份：

```bash
systemctl start homework-backup.service
journalctl -u homework-backup.service -n 10 --no-pager
```

查看后端日志：

```bash
journalctl -u homework.service -n 50 --no-pager
```

备份目前保存在同一台服务器，本地原数据也已保留。后续按使用量检查磁盘，并把重要备份另存到用户授权的独立存储中。
