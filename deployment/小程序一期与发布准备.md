# 小程序一期与发布准备

## 当前状态

现有交付物是 React 网站和 Node + SQLite 后端，不是小程序代码。可以复用账号、课表、模板、作业与完成状态、提醒偏好的业务和数据库；客户端页面和请求会话需要适配，不能将网站文件直接当作已开发完成的小程序。

暂按微信小程序准备；平台、注册主体、AppID 与已有工具需要用户确认。尚未下载开发者工具、安装新框架或新增依赖，没有上传、提审或发布。

## 一期建议范围

- 学号密码登录、首次改密和主动改密，忘记密码联系班委重置。
- 工作台：后续三个有课日期、排序后的三个待办作业。
- 我的课表：日、周、月浏览；模板与课程卡片选择优先做，复杂表格导入保留网站入口。
- 我的作业：查看课程作业、添加个人作业、调整优先级和个人计划、标记完成和撤销。
- 提醒设置：复用账户偏好。微信实际通知另行接通，不能把保存开关当成已获得订阅或已发送成功。
- 管理工作继续由网站承载：批量建号、学期校历、模板与作业导入。不在一期小程序中重复制作完整管理后台。

范围为建议，实施时保留学生与管理员个人身份的业务能力，并维持个人数据与管理页面隔离。

## 共用后端需要完成的适配

现有网站依赖浏览器 Cookie 和 Origin 校验。小程序请求需验证会话保存、续用、过期、退出、改密失效和来源策略，不能为支持小程序直接关闭网站的跨站请求保护。任何令牌仅用于本人会话，不能置于链接中；小程序包内不放 AppSecret、服务器凭据或数据库。

学生数据可见范围、学期由管理员维护、个人安排优先、完成状态按用户保存等规则保持一致。同一账号在网站与小程序的更改都写入同一数据库。

通知接通前需要确认小程序后台可用能力、消息模板和授权方式；再实现账号与接收人的对应、发送任务、发送前重新校验完成状态、失败重试和通知跳转。已有完成操作与发送前检查可复用，尚无真实发送器。

## 发布准备顺序

1. 确定代码仓库，完成首次上传和可回退版本。
2. 确定服务器和域名，先部署网站与共用 API，完成 HTTPS、数据备份与登录验收。
3. 注册/确认微信小程序主体、AppID、开发者权限和服务类目，并行启动所需备案。
4. 编写小程序原生页面和请求适配，连接同一后端，在开发者工具与真实手机验证。
5. 准备名称、图标、简介、用户隐私说明、实际服务类目和审核所需测试账号；测试账号使用独立数据。
6. 上传体验版，核对权限、课表作业与通知表现，再提交审核。审核通过后正式发布。

今天的开发与部署进度、备案进度、平台审核进度分别记录；不承诺当天审核通过或上架。
